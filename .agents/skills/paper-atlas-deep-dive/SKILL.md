# Paper Atlas Deep Dive

## 目标与触发

把论文变成**能独立复原机制、数学、工程执行与证据边界**的中文技术文章，而非摘要、笔记清单、逐段翻译或图文堆砌。针对新论文、旧稿重构、模型间对照和连续小批次（通常 2–4 篇）均适用。

本 Skill 的“完成”含义是：读者能回答 **为什么有这个问题、朴素修法为什么不够、作者如何改造、公式与数据流如何工作、实验证明到哪一步、这个技术被哪些模型采用**。严禁只凭篇幅、章节数、图片张数或结构检查宣布出版级完成。

按需读取：
- [论文类型与推演结构](references/paper-modes.md)
- [学术证据与推导质量](references/evidence-and-math.md)
- [跳转网络与可视化](references/navigation-and-visuals.md)
- [文章起稿骨架](assets/article-starter.md)（仅作启发；不可把它当统一标题模板）

## 在本仓库内的工作边界

1. **所有本地读取、搜索、脚本运行和写入限定在当前仓库目录树内**；不要遍历 E 盘其他位置或自动寻找同名工程。
2. 只编辑 `papers/A/`、`papers/B/`、`papers/C/` 等**真实稿件源文件**，以及任务需要的 `figures/`、`figure_manifests/`、`docs/reading-path.md`、`docs/technology-map.md` 与本 Skill 文件。
3. `docs/generated/`、`site/` 是生成结果，不手工在其上编辑正文；使用 `tools/build_site_sources.py` 与站点工具按需再生成。不要覆盖旧稿或清理旧文件，除非用户明确要求。
4. 本地代码/文件修改使用当前可用的、经过授权的工作区写入工具。不要通过只读诊断命令绕过写入限制；不要启动大规模训练或重型计算。工具不可达时说明限制，绝不声称已写入。
5. 外部检索以论文官方 PDF、版本化 arXiv、作者页面、官方源码与可靠学术后续工作为优先；不把搜索摘要、博客转述或无来源的数字当一手证据。

## 执行步骤

### 1. 锁定论文与类型

先在 `papers/` 查是否已有该篇/相邻专题，阅读 `docs/reading-path.md`、`docs/technology-map.md` 中相关节点。确认论文标题、版本、真实贡献和是否已被模型主线引用。随后**选择唯一主范式**：

- **B 模型/技术报告**：完整模型结构→实际训练/推理→规模与代价；先模型整体、后关键模块。
- **A 原始方法**：现实问题→原方法→失效原因→必须满足的性质→设计与推导→实验→采用者；无需虚构模型骨干或预训练。
- **C 系统论文**：baseline execution→profile/cost model→瓶颈→memory/compute/communication 调度→正确性→真实硬件表现；不可用 leaderboard 代替系统证据。

详细分支读取 `references/paper-modes.md`。遇到多属性论文时选主要贡献作为文章逻辑，其他属性在正文说明，不强套结构。

### 2. 先重建因果链，再写正文

在草稿外先确定：

**前代 → 当时的瓶颈 → 朴素修法 → 朴素修法局限 → 作者核心选择 → 公式/shape/执行流程 → 新代价 → 对照实验 → 失效边界。**

每节使用自然的疑问与承接；定义不是开头的全部。至少讨论一个可信的替代方案。区分**数学必然性**与作者**工程选择**，区分**作者原话/原表**与教学补充推导。

模型论文的关键组件只解释到能顺畅继续主线的深度；若数学仍阻塞，则创建或链接 A/C 原始专题**按需下钻**。不要从 Backprop 开始机械刷 A001→A166。

### 3. 补原文证据和读图说明

至少保留能解释核心方法的原始 Figure/Algorithm/Table（原文无可用图时允许没有，但注明缘由）。记录原文出处、版本、图号、页码或原源文件与 `figure_manifests/` 映射；亲自检查裁图是否完整。

先回答“作者想用它支持什么命题”，再解释轴/标签/条件，再指出“不能由它推出什么”。对于模型总榜，不推导单组件的独立因果效果。详细依据 `references/evidence-and-math.md`。

### 4. 画**教学解释图**，与原论文图分开

选对理解负担减幅最大的图：旧法 vs 新法、因果问题链、数据/张量流、训练阶段闭环、时间线、HBM/算力/通信对比。自制图写明“**自制解释图，非原论文 Figure**”。优先简洁可放大的 SVG/Mermaid；若工具支持图像生成/可视化也可使用，但不能牺牲学术准确性。

**图片不是越多越好**。每张图必须对应正文一个明确知识难点。见 `references/navigation-and-visuals.md`。

### 5. 建立真实可用的快速跳转

添加适量的顶部“前置 / 技术下钻 / 后续主线”，并在首次引入关键术语时**就地链接**。最后给“卡在 X → 读 Y”的路径。所有本地 `.md` 链接必须指向已经存在的文件；没有写成的论文用外部真实原文 URL 或文字“待写”，不能创建虚假站内链接。同步维护受影响的知识图谱和阅读路线。

### 6. 优先写博客论述，再做论文细读

主体使用**中文硬核技术博客**笔法：直观困惑开场、无跳步推导、局部例子、连接工程取舍、回到论文实验。避免机械标签化段落、日志化语言（“本批次、验收、读者应该、Agent 已完成”）与过密小标题。

论文细读只重点分析**高价值论证转折**：作者为什么此处引入定义、如何承接上一段、是否使用 hypothesize/suggest/prove/empirically、证据与措辞是否匹配；不是每个自然段等长度摘要。

### 7. 质量复核再更新状态

先做静态校验（本地图片/XML 可解析、相对链接、数学成对标记、代码围栏、唯一文章 H1）。本 Skill 自带：

~~~powershell
python .agents/skills/paper-atlas-deep-dive/scripts/audit_article.py papers/B/05-moe-complete-llm/B009-deepseek-v3.md
~~~

如果环境允许且用户要求站点验收，可按仓库 `README.md` 顺序执行轻量站点构建与链接检查，**不要**手工修 `docs/generated/`。视觉渲染、数字复算、官方图源匹配和科学表述需要**独立人工判断**；“静态 PASS”≠“科学终审 PASS”。代码例子未真正执行时明确注明“未运行”。

### 8. 汇报

反馈真实修改的文件、几个最重要的读图/公式/链接变化、已经运行的检查与**仍未核实**的项目。批量任务按影响面先做主干再做依赖文章，不以空泛进度报告代替交付。输出文章本体不要混入内部验收文字。

## 避免的失败模式

- 把 AdamW/GRPO/RoPE 强套模型“输入—骨干—预训练—部署”六段式。
- 把 DeepSeek-V3 使用 MLA/DeepSeekMoE 误说成 V3 首创。
- 用“更高效”替代 FLOPs、HBM IO、KV 容量、通信量、latency 的具体区分。
- 从原始论文复制几张图不解释，或给自制图贴“论文原图”标签。
- 把 A/B/C 不同实验、token budget 或模型规模的最终成绩混成因果证明。
- 给未写出的文章添加看似可点击的无效相对链接。
- 在公开站点正文泄漏任务流水、源文件 manifest、内部审阅或私人路径。
