# 证据链、数学和科学审读

## 一手证据优先级

1. 论文的**明确版本**（arXiv vN、会议正式版或出版版）与 PDF 正文/附录；
2. 作者的代码、配置、commit 与维护说明（明确论文与代码可能不完全一致）；
3. 原始方法的首篇工作、公开正式文档；
4. 后续可靠复现/批判性论文；
5. 二手综述仅作定位，不能替代主证据。

文章首部标明论文标题、链接、版本（**核对后才写日期和 vN**）；如多个版本表述不同，明确当前采用哪个。不得仅凭文件名猜 PDF 版本。技术贡献标明 `PROPOSES / ADOPTS / EXTENDS / DERIVED_FROM / IMPLEMENTS / OPTIONAL`，每条重要关系要找论文证据，不要按时间想当然。

## 一条完整“主张 → 证据”审计线

针对每个核心结论在起草时建立内部对应关系：

| 维度 | 应核对内容 |
|---|---|
| 具体主张 | 为什么快/准/省内存/可扩展？到底指哪项指标？ |
| 证据位置 | 哪个 Table/Figure/公式/原文段落、页码或图注 |
| 对照 | baseline 同模型/同数据/同超参/同硬件吗？ |
| 干预变量 | 真正只变了哪个模块，还是同时改了数据、规模或训练 recipe？ |
| 读数 | 单位、精度、范围、显著性、测试条件 |
| 证据强度 | 数学证明、同条件消融、观察、case study、作者假说 |
| 边界 | 反例、失败条件、未报告条件、无法归因的收益 |

在正文里自然地表达证据强度：`作者观察到`、`作者提出假设`、`在该配置的消融中`、`按我们复算`。严禁把 `suggest` 改成“证明”，或把跨模型最终 leaderboard 当某层改动的因果证据。

## 第一性数学推导

- 先定义变量、shape、目标函数、约束，然后才开始变换。
- 旧方法为何不满足需要先用一个反例或计算事实说明。
- 从必要性质→构造候选形式→检验性质→近似/优化选择；不要事后把“作者选择”包装成唯一必然。
- 多行等式必要时拆步，说明用到的恒等式、独立性、正交性、重参数化和尺度条件。
- 公式一律 `$...$`、`$$...$$`，行间公式独立成段；真正代码名才写 `反引号`。
- 对工程效率说明清楚统计口径：weights / activations / KV cache / optimizer states / HBM IO / MACs / FLOPs / communication / runtime。
- 给至少一组小数值/Shape 例子，**可复算且标明假设**。
- 若算法存在随机性/边界，说明 clip、eps、全 0 reward、空专家、padding、mask、长度归一化、有限精度、overflow 等适用条件。

## 原论文与代码

原论文图/表不是装饰。每张图：先指出**应看哪条曲线/箭头**，再讲它支持的主张、测量条件和不足。

若提供代码：
- 区分演示性伪代码、真实 PyTorch 代码、作者官方代码；
- 指定 shape、device/dtype、forward/backward 更新顺序；
- 必要时做小输入验证或有限差分；
- 不编造“已运行通过”；
- 不为讲解目的在用户机器启动重型训练。

## 学术语言“证据边界”

高价值句子需要辨别：
- `we hypothesize / conjecture`：假说、设计动机；
- `we observe / suggest`：观察与解释；
- `empirically demonstrate`：给定任务的经验支持；
- `prove / theorem`：明确条件下的理论结论；
- `we believe`：展望，不是被证明的事实。

“论文细读”侧重高价值论证转折（Introduction、Method 开头、关键消融和 Discussion），不是逐段平均复述。引用原文少量短语即可，不长段翻译整篇。非自有图片遵守论文授权与公共发布许可；未经授权的原图不应自动公开发布。

## 每篇新稿和返工稿都必须进行的人工审查（不得用关键词计数代替）

本表不是要把标题照抄到文章里，而是审稿人必须**能用原论文和当前稿件指出具体证据**；发现问题时直接修改文章，不在公开页堆“待完善/检查通过”的过程描述。

| 必审项 | 什么才算通过 | 典型伪通过 |
|---|---|---|
| 贡献归属与版本 | 说清论文首创、继承、采用或只作为设计空间展示的组件；核对具体版本 Figure、Algorithm、Table | 作者仅把候选 Layer 画入图，文章却声称发布模型已采用 |
| 机制可复原 | 从已知条件推到更新式/算子数据流，写清 Shape、反向步骤、边界和一个非平凡手算/可执行演示 | 只写总公式、参数定义和几句“实现高效” |
| 真正读图 | 至少精读一处论文原始关键图/算法/表，解释每个关键标签、变量和作者真正要支持的命题 | 只给论文 PDF 链接、写一张抽象 Mermaid 总览 |
| 独立科学核对 | 源码或原论文证实符号方向/下标/转置/归一化；抽样、数值和手算与正文一致 | 有大量公式但没有重建等式，错一个下标自动审计也不会报错 |
| 实验因果 | 明确同条件消融、跨论文对照、不同 tokenizer 或训练配方、评分协议；负结果不能被删去 | 把不同模型/预算的最终榜单差写成一个方法的独立收益 |
| 教学可读性 | 每节从上个难点自然过渡，图/公式后解释“具体看哪一步”，读者能在本篇重建核心操作 | 小标题很多、每段都浅尝辄止，最后用“边界”模板凑篇幅 |

**批量返工时先排序再落稿**：优先修复数学/图号/模型实际结构的错误，其次补算法、数值和原始证据，最后处理图片导航与排版；不要先扩写无错误的概览段来冲页数。允许部分文章保留“未完成人工复核”状态，但严禁仅凭静态工具全绿把全库宣称为出版级完成。
