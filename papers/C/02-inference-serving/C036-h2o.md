# H2O：历史 Attention Heavy Hitter 能否成为 KV 驱逐准则？

> **原始论文**：[H2O: Heavy-Hitter Oracle for Efficient Generative Inference of Large Language Models](https://proceedings.neurips.cc/paper_files/paper/2023/hash/6ceefa7b15572587b78ecfcebb2827f8-Abstract-Conference.html)，NeurIPS 2023。 [官方/作者 PDF](https://proceedings.neurips.cc/paper_files/paper/2023/file/6ceefa7b15572587b78ecfcebb2827f8-Paper-Conference.pdf)。


从 [StreamingLLM 的 Sink 保留](C035-streamingllm.md) 出发；对照 [SnapKV 的 Prompt 观察窗口](C037-snapkv.md) 与 [KIVI 的低比特缓存](C038-kivi.md)。

## 删除旧缓存之前，我们究竟知道它有没有价值吗？

假设每个 Token 的 Key/Value 共占 $B$ 字节，当前 Prompt 为 $L$，每生成一个 Token 就需要读取越来越多历史 KV。如果预算只允许留 $M<L$ 个历史位置，最容易想到 **FIFO/最近窗口**：旧 Token 先出。但有些早期变量定义、系统约束或跨段引用在后面的生成中仍是关键证据。纯按时间驱逐并不能体现每个 Token 实际被关注的程度。

H2O 的实证发现是：一小部分历史 Token 在许多后续 Query 中反复取得较大 Attention 权重，可以作为重要位置的 proxy。作者称其 **Heavy Hitter（重度命中）**。它与 [Attention Sink](C035-streamingllm.md) 不一样：前者旨在估计持续受到关注的历史信息贡献，后者强调即使**语义不重要**也可能吸收 Softmax 概率的固定开头位置，两者存在交集但不能等号相连。

## 从分数定义到维护策略

用 $a_{u,j}^{(\ell,h)}$ 表示某层 $\ell$、头 $h$ 的第 $u$ 次 Query 对历史 Key $j$ 的注意力权重。一种直观的历史贡献统计是

$$
s_j(t)=\sum_{u=j}^{t}\sum_{\ell,h}
a_{u,j}^{(\ell,h)}.
$$

这是说明“累计关注程度”的教学公式，并非声称所有层/头在原实现中无权重直接求和；论文具体的注意力打分累计和 Token 预算应查对应 Algorithm。该分数最大的问题是**只知道过去**：位置 $j$ 从未被强烈关注，不代表下一 Token 不会突然引用它。

因此 H2O 不只选高分，还同时保留一部分最近窗口 Token。其概念性的选择是

$$
S_t=\operatorname{TopK}_{j\le t-n_r}s_j(t)
\;\cup\;\{t-n_r+1,\ldots,t\},
\quad |S_t|\le M.
$$

在总预算 $M$ 下，$n_r$ 和 Heavy Hitter 预算之间存在挤占。近期缓存为了支持局部语言流畅与尚未积累 Attention 的新证据；高分缓存为了延续长期受关注的信息。删除某位置后，未来 Query 已无法再从原缓存中计算对它的分数，因此这是**不可逆的在线选择问题**，不是离线获得完整未来注意力矩阵后的最优截断。

## 为什么论文谈到 Submodularity？

缓存选择可能不是逐 Token 收益独立相加。一个 Token 的边际价值依赖当前已选集合 $S$；若选择集合的质量函数 $F(S)$ 具有次模性质，则

$$
F(A\cup\{x\})-F(A)\ge
F(B\cup\{x\})-F(B),\qquad A\subseteq B.
$$

这表示集合越大，加入同一个元素带来的边际收益不增加，是组合优化中“收益递减”的条件。H2O 把 KV 驱逐建模为动态次模选择，并在**特定假设**下给出贪心算法的性质；不能据此说任何真实 Transformer 的最终任务正确率都是次模函数。理论分析指导预算策略，实际可用性依赖论文的经验结果。

## 一个有界缓存在线选择的完整例子

假设 Token 历史长度已经为 10，缓存预算只能留 5 个位置，其中要求保留最近 2 个 Token，即位置 9、10；另外 3 个位置从先前的 1–8 中选择累积 Attention 分数最高者。若历史分数为

$$
s=(1,10,2,1,9,1,8,1),
$$

那么 Heavy Hitter 集合是 $\{2,5,7\}$，最终缓存位置为

$$
S_{10}=\{2,5,7,9,10\}.
$$

生成 Token 11 时，应当先计算**当前还能访问的缓存位置**上的 Attention，再更新相关统计，接着按照预算进行驱逐；不能回头计算已被永久删除的 Key 的新 Attention。这里的示例分数是人为构造的直观版本，真实 H2O 实现需要正确维护不同头/层与之前保存状态的分数、预算和更新顺序。

### 为什么“每次保留 TopK 分数”也不一定是完整算法？

分数来自历史 Attention，因此未曾被 Query 强烈访问的位置可能是当前任务即将需要的信息；完全依赖 TopK 会丢失尚未积累证据的新 Token。因此 H2O 把**最近窗口**与**历史 Heavy Hitter**共同放进预算，而不是简单地“旧 Token 按分数、最新 Token 自生自灭”。在一些低缓存比率下，预算分配比例就是主要超参数，不可仅复制论文的“20% Heavy Hitters”成适用于所有场景的固定常量。

## Submodular Guarantee 的假设边界

对任意集合 $A\subseteq B$，若一个集合效用函数 $F$ 对新增位置 $x$ 具有边际收益递减性质：

$$
F(A\cup\{x\})-F(A)\ge F(B\cup\{x\})-F(B),
$$

则称它次模。这个属性使贪心近似可以获得有条件的理论保证。但真实 Decoder 的 $p(y\mid\text{保留的 KV 集合})$ 会经过 Softmax、残差和多层非线性计算，**并没有因此得到“整个 LLM 准确率是次模函数”的一般性定理**。H2O 的理论是在特定建模与假设下分析缓存选择，不能把证明对象随意换成任意下游任务。

[NeurIPS 2023 H2O 正式摘要](https://proceedings.neurips.cc/paper_files/paper/2023/hash/6ceefa7b15572587b78ecfcebb2827f8-Abstract-Conference.html) 明确把实验基线区分为 DeepSpeed Zero-Inference、HF Accelerate、FlexGen，并报告不同吞吐倍率。一个公平比较须固定模型、Batch、序列长度、缓存预算和 Offloading 策略；否则大量提速可能来自避免 Offloading 而不只是 TopK 选择本身。

## 如何避免“保留高分 Token 就代表保留语义”的误读？

若系统 Prompt 的格式 Token 持续获得高注意力，也可能成为 Heavy Hitter；这不是独立的语义重要性测度。反过来，长文末尾突然要求引用开头低注意力的段落，在线驱逐也可能失误。比较应区分 KV 占用、困惑度、摘要/检索任务准确率、生成延迟，而不是只看一个 attention score 的可视化热图。

作者 [NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/6ceefa7b15572587b78ecfcebb2827f8-Abstract-Conference.html) 在 OPT-6.7B/OPT-30B 及受限内存部署下，报告吞吐相对不同基线最高 **29× / 29× / 3×**，相同 Batch 的延迟最高下降约 **1.9×**。这三组比较对象分别是 DeepSpeed Zero-Inference、Hugging Face Accelerate 和 FlexGen，不能写成与所有现代 GPU KV 管理器比提高 29×。

**工程追问**：在每个 Layer/Head 保持哪些 Token？分数在读取哪些 Query 时更新？如果高优先级 KV 被显存碎片化，驱逐实现是否比省下的 Attention 时间还贵？下一篇 [SnapKV](C037-snapkv.md) 利用预生成的 Prompt 后缀集中判断重要位置，改变了“何时评估价值”。
